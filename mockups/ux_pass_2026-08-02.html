Sim Lab — UX pass

2026-08-02. Proposal only: this document changes nothing in web/. Observed in the running app against a live engine — 29 decks, 58 finished runs — at 1280 px and 375–533 px.

Binding constraint: the UI does not change. Same tokens, same type, same components, same look. Everything proposed here is information architecture, responsive behaviour, or removing things that should never have been on screen. No new colour, no new visual language, no redesign. Every frame below is built from arcane-sim-lab.tokens.css and existing class names.
01 — Information architecture

Two whole modes of the product have no address

Deck exploration and the goldfish sandbox both exist and both work. Neither is in the nav. The only route into a deck page is a Cards pill on a tile inside /new — the simulation setup page — or an "Open deck →" link inside a hover popover that is display:none below 980 px. On a phone, that second route does not exist at all.

Meanwhile Import occupies a top-level slot even though it is one action performed on decks, and New run is a verb sitting in a list of nouns.

Now — 4 items, 2 orphans

/newNew run — a verb, and the page does two unrelated jobs: browse every deck and configure a gauntlet
/importImport — a sub-action of decks, promoted to a peer of Results
/resultsResults
/rulesRules
/decks/[file]orphan — reachable only from a tile inside /new
/playtest/[deck]orphan — reachable only from a deck page, or a popover that doesn't exist on mobile

Proposed — 5 items, all nouns, all places

/decksDecks — the gallery, lifted out of /new. Import is the primary action here.
/newSimulate — picker + games + run. Route unchanged; it stops being a browser.
/playtestPlaytest — deck chooser → sandbox

On the home hub, "Explore decklists" and "Run new simulation" both point at /new today — two of four buttons going to one place, which is the clearest symptom of the orphan. Explore repoints at /decks. The hub stays four buttons; nothing is added.

02 — Global chrome

The breadcrumb duplicates the H1 and costs us the nav

Chrome.tsx renders brand / <context> on the left. The context string is always a restatement of the H1 forty pixels below it. On desktop that is duplication. On a narrow screen .path is white-space:nowrap and .tb-links has margin-left:auto with no wrap rule — so the breadcrumb pushes the nav off the edge.

06 — The two new front doors

/decks and /playtest

Neither page needs new components. /decks is the gallery that already exists inside /new, with the search and colour filter it already has and Import as its primary. /playtest is the same gallery with a different verb. 09 — Touch

Targets under 44 px, and controls that only exist on hover

Undersized targets

  • .dg-view "Cards" pill — 24 px
  • .pt-mini life ± — 26 px
  • .vbtn transport — 34 px
  • .tab Overview/Telemetry/Coaching — ~40 px
  • .pt-card .cbtns button counters — 18 px

--control-h: 44px already exists as a token. These take it under @media (pointer: coarse). No new values.

Dead on touch

  • .pt-card .cbtns is display:none until :hover — there is no way to put a counter on a permanent from a phone. Becomes always-visible at pointer: coarse.
  • .dl-pop decklist popover is hover-triggered and display:none below 980 px, so its "Open deck →" and "Playtest →" links don't exist on mobile. The real fix is §01 — both destinations get nav entries, and the popover stops being load-bearing.
  • .dg-tile opens the popover on mouseenter; on touch the first tap seats the deck with no preview at all.
10 — Smaller, same pass

Loose ends worth closing while we're in here

  • Home's "Top decklists" rows link to /results?q=<name>. The heading says decklists; clicking one should open the deck. Repoint at /decks/<file>, keep "see its runs" as a secondary.
  • .deck-row__thumb is a hardcoded diagonal-stripe placeholder where commander art belongs — the only pattern in the sheet that isn't a token. Replaced by the §05 fallback plate.
  • /rules wastes its right column. "Rule text" is an empty panel holding two paragraphs of apology until you ask something. Collapse to one column until there is an answer to sit beside.
  • GET /decks returns commander: null for all 29 decks on the local engine, so the gallery has no art anywhere. combos.parse_dck parses the same files correctly in isolation, which points at a stale server process rather than a code bug — verify on the VM before changing anything. The design fix (an honest fallback plate) is worth doing either way.
  • Four runs are titled Kilo vs Atraxa vs Ur-Dragon vs Meren. The date is the differentiator and it is the fourth column. It moves into the row's second line at every width (§04).
  • The engine-address control is duplicated on home and inside /new's section header. One instance, in the nav sheet / overflow.
