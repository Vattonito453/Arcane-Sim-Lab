# Sim pipeline deep audit — 2026-08-03

Five parallel audits over the full sim pipeline, triggered by the
timeout-declares-a-winner bug (83% of 4-pod games were clock-forced fake
wins, invisible until a manual raw-log audit). Scope: orchestration
(run_sim/worker/jobqueue/mtg_engine), the shim's Java (verified against
Forge 2.0.13 bytecode), the log adapters and stats (with executed repros),
result presentation vs SIM_CALIBRATION.md, and the humanized decision
layer (corroborated against 16 games of raw agent telemetry).

Findings are numbered A1..A24, grouped by theme, most severe first.
"Verified" means the auditor read the full code path, decompiled the
relevant Forge bytecode, or ran a repro — not speculation.

---

## Theme 1 — Statistical validity: the numbers rest on broken assumptions

**A1 (critical). Games in a run are not independent, and draws hand seat 1
the next first turn.** Verified in Forge bytecode: `Match.startGame` feeds
`lastOutcome` into `determineFirstTurnPlayer`, which picks the earliest-
seated non-winner of the previous game, and that player's AI controller
always chooses itself to go first. Game 1 is random; every later game's
first-turn advantage is assigned by prior results. After ANY draw
(= every timeout), nobody `isWinner`, so **seat index 0 always goes first
in the next game** — an absolute seat bias that upstream seat rotation
cannot cancel, active in a large share of games given the historical
timeout rate. Fix: fresh `Match` per game, or `match.clearGamesPlayed()`
between games. (SimShim.java:157,168-170)

**A2 (high). Per-seat RNG streams are identical in every game.** The
controller seed is `7919L*(seat+1)+id`, reconstructed identically each
game. The first `splitAttacks` roll at a given seat is the same number in
every game of every run — personality dials (splitAttacks, blockiness,
triggerMiss, greed) quantize toward always/never at correlated decision
points instead of expressing their probabilities. Fix: mix the game index
into the seed; record the seed in the meta record. (SimShim.java:141,
PlanLobbyPlayerAi.java:34-35, PlanPlayerController.java:58)

**A3 (medium). Mirror pods (same deck in two seats) collapse stats.**
`_summarize_by_deck` (run_sim.py:328-330) and analysis.py:276-277 key by
bare deck name — a 4-seat pod with a duplicate reports as 3 keys,
corrupting pod size, the even-seats baseline, and combo conversion
attribution. `/simulate` accepts duplicate deck names without complaint
(mtg_engine.py:965).

## Theme 2 — Silent data corruption between Forge and the result file

**A4 (critical). A crashed game is emitted as a legitimate draw.**
ExecutionException/InterruptedException in the game thread prints to
stderr, then the normal emission path runs: partial log, partial zones,
`{"draw":true,"winner":null,"turns":-1,"timedOut":false}` —
indistinguishable from a real draw downstream (nothing reads turns:-1).
Crashes silently inflate draw rates; a crash after `setGameOver` can even
emit a plausible winner. Fix: emit `"error":true` + exception class; the
Python side quarantines it. (SimShim.java:276-277,316-329)

**A5 (critical). Partial rotation failure is silent; the merged result
claims completeness.** Shim path: nonzero shim exit → stderr warning only,
partial jsonl parsed and merged, run_sim exits 0 (run_sim.py:140-141).
Stock rotated path: returncode never checked at all (:292-317). Worker
accepts `rc==0 and games>0` — one surviving game of 16 → job `done`
(worker.py:38). A rotation that OOMs leaves `meta.rotations: 4` claiming
full rotation with seat-bias cancellation partially broken, undetectably.
Fix: record per-rotation game counts in meta; worker compares played vs
expected; propagate sub-run failure.

**A6 (critical, repro'd). One lost shim result record merges two games and
shifts zones/agent_events/timedOut onto the wrong games.** parse splits on
"Game Result" lines only; the game index in the line is captured but
unused; the positional zip then misaligns everything after the gap, and
the summary hides the timeout. A truncated JSONL line (OOM-kill mid-flush)
is enough. Fix: match on the game number already present in the line;
assert parsed count == len(game_order). (shim_log_adapter.py:64-65,83,
106-121; forge_log_adapter game splitting)

**A7 (critical). Stock-Forge runs record clock-cut games as WINS —
verified in the historical logs.** Real pre-shim logs contain
`java.util.concurrent.TimeoutException` followed by "Game N ended in
240002 ms. X has won!", disproportionately crediting late seats; the
adapter counts every one as a real win and `timeouts` stays 0 by design
for stock runs. The stock path is still reachable: run_sim silently falls
back to stock AI when the shim jar is missing (run_sim.py:158-168).
`duration_ms >= clock*1000` is a verified-reliable timeout signature for
retroactive flagging. (forge_log_adapter.py:51,84-86)

**A8 (critical). Plan lookup silently degrades seats to stock AI while
the run stays labeled humanized.** `plans.get(d.getName())` — a name
mismatch (filesystem-sanitized deck names make drift likely) falls back to
stock AI with only a stderr line; meta `humanized` is true if ANY plan
loaded. A mixed pod is a different experimental condition and nothing
downstream can tell. Fix: per-seat agent types in the meta record;
hard-fail when --plans was given but a deck has no plan.
(SimShim.java:138-148,164)

**A9 (critical). AgentLog misattributes a zombie game's telemetry to the
next game.** AgentLog is a process-global with one volatile game index; a
game thread that survives the 15s post-timeout grace keeps logging into
the NEXT game's index. EventTap does this correctly (per-instance index) —
AgentLog should match. (AgentLog.java:19-30, SimShim.java:255,273-279)

**A10 (high). Reading the game log after a failed unwind is a data race
that can kill the whole run.** GameLog's backing ArrayList is
unsynchronized; a concurrent add during array growth can yield a null
entry → NPE at `e.type().toString()` → process dies → no result records
for remaining games, and the truncated JSONL is accepted downstream
without error. (SimShim.java:283-306)

**A11 (medium). An unfinished trailing game inflates the denominator of a
FINISHED result file.** A game with entries but no result (JVM killed
mid-game) is kept with `result: None` and counted in games without
contributing a win or draw — deflating every deck's win rate. analysis.py
also assigns it a win method. (forge_log_adapter.py:65-69,133,173-179)

**A12 (medium). ~~Stale staged deck copies silently substitute.~~ FIXED
2026-08-04.** Staged .dck copies in Forge's profile dir were never cleaned;
if the source vanished (deck deleted between enqueue and claim — TOCTOU)
the stale copy was used without even a log line. The basename-keyed shared
dir also broke under any second producer. (run_sim.py:88-100)

Fix: each shim invocation now stages into its own private profile under
`<forge profile>/simlab-runs/`, removed on exit, with a 24 h sweep for
runs that were killed. The shim takes absolute .dck paths so it does not
care where that folder is; stock Forge's `sim -d` resolves names from its
real profile, so that path deliberately keeps the shared folder and warns
instead. A missing source is now fatal rather than falling through to a
stale copy. Regression tests in `engine/tests/test_staging.py`, verified
to fail against the old behavior, plus two concurrent live sims confirmed
isolated end to end. **A13 (result-file attribution by mtime window) is
still open and is the remaining multi-worker hazard.**

**A13 (medium). Result-file attribution is mtime-window, not identity.**
The result JSON never carries the run_id (only raw logs do); the engine
takes the newest file in a shared dir written after t0. Any concurrent
producer (second worker, embedded-worker misconfig, manual run) can get
its result credited to another job. Fix: put run_id in the result
filename. (mtg_engine.py:185-191, run_sim.py:200-280)

## Theme 3 — The clock: a new time bomb and the fix that didn't ship

**A14 (critical). The 900s clock vs the 2h job kill: legitimate jobs are
now killable and everything is discarded.** One run_sim invocation covers
ALL rotations under a single `MTG_SIM_TIMEOUT_SECONDS` (default 7200s,
NOT overridden on the VM — verified). 16 games worst-case = 14,400s;
64 games (SIM_MAX_GAMES) at the measured MEDIAN pace = 10,176s — the max
request cannot complete at median speed. On TimeoutExpired no result JSON
was ever written: every completed game is discarded, job errors with
"killed after 7200 s". Completed rotations' raw JSONL files survive on
disk but nothing salvages them. Fix: scale the outer timeout from
games×clock (+ per-rotation JVM startup), and salvage completed rotations
on kill. (mtg_engine.py:175,180-191; run_sim.py:206,232,281)

**A15 (high). The kill doesn't reach the JVM.** subprocess timeout kills
run_sim (direct child) only; the JVM is a grandchild with no process-group
kill. The code comment assumes Forge dies on EPIPE at its next stdout
write — but Java PrintStream swallows IOExceptions, so the orphaned 4GB
JVM most likely runs to completion, starving the next job on the 2-vCPU
VM. Needs a live test + process-group kill. (mtg_engine.py:170-178)

**A16 (critical). The `timeouts` counter shipped on 2026-08-03 does not
work on the default path.** `_summarize_by_deck` (run_sim.py:320-340)
rebuilds the merged summary for every ROTATED run — the default — from
scratch, with no timeouts key; the per-rotation counts are discarded.
Independently: `summarize()` still CREDITS the win on a timed-out game
that carries a winner (forge_log_adapter.py:165-172), so re-parsing
polluted files re-mints fake wins. And no web surface renders timeouts at
all (SimSummary in web/lib/types.ts lacks the field). Three auditors
converged on this independently.

**A17 (medium). Coupled timeout constants with no cross-check, and
finish() has no state guard.** reap_stale (3h default) vs the outer kill
(2h): safe today, but raising MTG_SIM_TIMEOUT_SECONDS without
MTG_JOB_TIMEOUT_SECONDS makes /sim-status polls flip a live job
running→error ("worker was lost, start again" → user enqueues a
duplicate), then the worker's unconditional finish() resurrects it
error→done. Fix: `WHERE state='running'` guard on finish(); startup
assertion tying the two env vars. (jobqueue.py:53-57,79-97)

## Theme 4 — Decision layer: the tokens & combo-triggers report, explained

**A18 (critical). Stage 5 tutor steering is structurally dead.** The
line-of-sight gate opens because a tutor is in hand; when the search
RESOLVES the gate is re-evaluated — but the tutor is now on the stack,
not in hand, so the gate reads closed and the steer never fires. Stock AI
picks the search target. Corroborated: across 16 games of telemetry,
164 search_seen events, one sighted=true (nothing to steer), zero
tutor_steer. Combo conversion rates are unaffected by the entire pursuit
mechanism. (PlanPlayerController.java:405-443,622-638)

**A19 (critical). triggerMiss fizzles active combo loops.** The 3% miss
roll re-rolls on EVERY optional-trigger confirmation with no exemption
for plan-line cards: an "infinite" token loop iterating a "you may"
trigger (e.g. Siona + Shielded by Faith, in this repo's own combo cache)
halts after a median ~23 iterations, every game. The deck assembles its
win and stops — exactly "weird behavior with combo triggers". Fix: skip
the miss roll for cards in plan.lines. (PlanPlayerController.java:359-375)

**A20 (critical). Illegal menace blocks stand.** The danger-mode block
loop uses the 2-arg CombatUtil.canBlock (no combat context, no
min-blocker check); verified that Forge's AI-path post-processing strips
only blocker-side violations and never runs validateBlocks. A single
chump declared on a menace attacker resolves a game state real Magic
forbids. (PlanPlayerController.java:277)

**A21 (critical when triggered). Deterministic kingmaker re-aim + Forge's
redeclare-until-valid loop = hung combat.** Re-aim moves the same
attackers every retry (no RNG, board unchanged); if the moved creature is
under an attack requirement (goad, curses), every retry is invalid and
the do-while spins at full CPU until the wall clock force-draws a
winnable game. None of the current bundled decks obviously carry goad —
any imported deck can. Also: every benign retry re-runs humanizeAttacks,
duplicating split/kingmaker telemetry. (PlanPlayerController.java:199-223)

**A22 (medium). The kingmaker never lets anyone die, and fires
constantly.** weakestThreat clamps to max(1.0, …) so one 4-power creature
makes a "runaway leader"; there is no lethality check, so attacks are
pulled off a seat even when lethal — humanized pods systematically
protect the quietest seat (usually the combo deck) and drag games to turn
42-55. This, not any single bug, is the likeliest driver of the 4-pod
timeout epidemic. Token interaction: the split then peels the
weakest-power third (tokens) onto the scariest seat, where they die.
(PlanPlayerController.java:199-223,647-657)

**A23 (medium, cluster). Token and value blindness in combat/counter
decisions.**
- Block ordering ignores plan weights: a cheap small combo piece
  chump-blocks just before the line assembles (valueOf = power+CMC+
  commander only). (PPC:272,684-686)
- Casual blocking throws the cheapest creature (in token decks: always a
  token) in front of ≥4-power attackers with no trade or trample check —
  pure card loss. (PPC:255-287)
- Counterspell threat bar: unknown spells cap at score 4 vs bar 5+, so
  anything not in a plan deck's threat index is structurally
  uncounterable; stock-AI seats' spells are never in the index.
  (PPC:340-348)
- Token boards read as ~0 threat for noncreature permanents (15 Treasures
  = nothing); creature tokens count power only. (PPC:647-657)
- Pseudo-tutors with graveyard destinations (Buried Alive) open the combo
  gate and can bury the missing piece where lineOfSight never looks —
  the gate then burns tutors on an unfetchable card forever.
  (deck_plan.py:99,189-191; PPC:579-638)

**A24 (medium/low, cluster). Plan-builder and dial defects.**
- Tag heuristic: "other " substring-matches "another " — every deck gets
  tribal-anthem; "create a"/"token" match every Treasure/Clue maker;
  false positives get weight 5-8 and mulligan/keep priority.
  (deck_plan.py:36,46,158,194-197)
- `aggression` is parsed but referenced nowhere — a dead dial in every
  archetype. (DeckPlan.java:73)
- Pursuit can't cast the commander (lineOfSight counts command zone;
  comboPriority iterates hand only). (PPC:409,473)
- Counter "twitch" re-rolls per priority pass (effective rate >> 10%);
  the veto discards the whole stock action list; grudge never accrues
  while the victim has no untapped creatures. (PPC:297-338,242-248)

## Theme 5 — Presentation: corrupt data flows to users unmarked

**A25 (critical). No pollution gate anywhere.** Home leaderboard, home
tallies, analysis.py, deck_telemetry.py, and coaching all consume
pre-2026-08-03 polluted results with zero validity checks; coaching
reports generated from polluted runs are cached forever with no version
stamp to invalidate them. Coach's freshness gate checks only
meta.source=="rotated" — polluted rotated files pass.

**A26 (critical). The results index strips meta.** _list_results emits no
meta.source / meta.humanized / timeouts, so no front-end surface CAN flag
non-rotated (seat-biased) or stock-vs-humanized runs. The 7/31–8/2
rotation-off window's files are indistinguishable in every list. A
non-rotated run's only tell on the report page is the absence of the
word "seat-rotated". The telemetry page's explicit "not seat-rotated"
warning is the in-house pattern to replicate. (mtg_engine.py:381-395)

**A27 (medium). Requested vs played games disagree across surfaces.**
`per = max(1, games // rotations)`: 1 requested → 4 played, 6 → 4,
10 (the worker default) → 8, 63 → 60. Run page shows requested; result
file and home tally show played; nothing reconciles or explains.
SIM_MAX_GAMES validates the requested number, not the played one (a
games=1 request runs 4 full games). (run_sim.py:188,219)

**A28 (medium, cluster). Calibration-doc violations in the UI.**
- No archetype baseline on the run report — only the even-seats 25%
  marker, the exact comparison SIM_CALIBRATION.md forbids as sole
  reference; an engine deck at 14% red-flags "below baseline" when its
  class average is 12%.
- meta.humanized displayed nowhere; coach stamps stock-AI archetype
  baselines onto humanized runs unqualified.
- Leaderboard: 100% win-rate fill bars off 1-game samples, no minimum-n.
- Win rates divide by games INCLUDING draws while the UI compares to
  1/pod — now that every clock-cut is a draw, heavy-timeout pods read
  far below an even share for all four decks at once.
- "Game N of M" live display resets each rotation unexplained; progress
  bar is a wall-clock fill, not game progress.

## Verified clean (hunted, no bug)

- triggerMiss can never illegally decline a MANDATORY trigger (Forge only
  consults confirmTrigger for optional deciders — bytecode-verified —
  plus the shim's own isOptionalTrigger guard). The combo-fizzle issue
  (A19) is about optional triggers.
- Per-game state isolation of the controller (grudge, mulls, holds) is
  correct; EventTap zone attribution is correct.
- JSON emission core escaping (quotes/backslash/control/unicode) correct;
  AgentLog.esc is the one incomplete copy (control chars).
- TYPE_TO_CAPTION covers all 19 GameLogEntryType constants in Forge
  2.0.13 (decompiled); message content cannot fake a caption or result
  line (anchored regexes).
- Winner-name matching lands exactly on seeded Ai(n)- keys (round-trip
  verified); _refs() attacker splitting is robust; no other comma/"and"
  split exists in the adapters.
- Combo-line names from Commander Spellbook currently match .dck names
  for all 15 cached decks (DFC/split-face mismatch is latent only).
- Blocks the shim adds are sanitized by Forge's blocker-side keyword
  checks (except the menace/min-blocker gap, A20).

## Test-coverage gaps

test_adapter.py covers stock parsing only. Zero unit tests for:

_summarize_by_deck (the summarizer production actually uses), analysis.py,
board.py, any nonzero-timeouts case, or the misalignment repro (A6). The

## Recommended fix order

Wave 1 — stop the bleeding (small, engine-side, no shim rebuild):
1. A16: timeouts in _summarize_by_deck + never credit timedOut winners +
   add timeouts/meta.source/meta.humanized to _list_results and
   SimSummary; render on report page. (Also A26.)
2. A14+A15: outer timeout = f(games, clock, rotations); process-group
   kill; salvage completed rotations on kill.
3. A5: per-rotation game counts in meta + worker played-vs-expected check.
4. A17: finish() state guard + env-var cross-check.
5. A27: fix `per` math (distribute remainder), store played vs requested.

Wave 2 — shim correctness (one rebuild, ordered by stats impact):
6. A1: fresh Match (or clearGamesPlayed) per game.
7. A4: error-flag crashed games; A9: per-game AgentLog; A10: guard the
   log read; A8: per-seat agent types in meta + hard-fail on plan miss.
8. A2: game-index in RNG seed; A6: game-number-keyed result matching
   (python side).

Wave 3 — decision quality (changes results; re-baseline after):
9. A19 (combo-loop triggerMiss exemption), A18 (re-evaluate gate at cast
   time / pass sighted piece through), A20 (3-arg canBlock), A21 (cap
   re-aims per combat), A22 (lethality check + threat floor fix).
10. A23/A24 clusters as a tuning pass with before/after gauntlets.

Wave 4 — historical data (A7, A25): quarantine or annotate pre-8/3
result files (timeout signature: duration_ms >= clock*1000, or
timedOut-carrying fake winners); stamp coaching cache with an analysis
version; re-baseline archetype numbers after Wave 3 since decision fixes
change win rates.

Waves 3+4 change measured behavior — SIM_CALIBRATION.md's numbers must be
re-measured after they land (working agreement: docs follow measurement).
