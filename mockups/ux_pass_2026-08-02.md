# UX pass — 2026-08-02

**Constraint set by Vincent:** don't change the UI. Same tokens, same type, same
components, same look. Every fix below is information architecture, responsive
behaviour, or removing things that shouldn't be on screen. No new colour, no new
visual language, no redesign.

Companion mockup: `mockups/ux_pass_2026-08-02.html`.

Everything here was observed in the running app (local engine, 29 decks, 58
finished runs) at 1280px and at 375–533px, not inferred from the code.

---

## 1. The four structural problems

### 1.1 The top bar renders a breadcrumb that costs us the nav

`Chrome.tsx` puts `brand / <context>` on the left and the nav on the right of a
60px flex row. The context string is *always* a restatement of the H1 sitting
40px below it — "New run / New run", "Rules assistant / Rules assistant",
"Ur-Dragon vs Atraxa vs Meren vs Kilo / Ur-Dragon vs Atraxa vs Meren vs Kilo".
It is pure duplication on desktop.

On narrow screens it is worse than duplication: `.path` is `white-space: nowrap`
and `.tb-links` has `margin-left: auto` with no wrap rule, so the breadcrumb
pushes the nav off the right edge. Measured at 533px on `/results/<run>`:
**"Results" and "Rules" are not reachable at all**, and "Import" is clipped
mid-word. The screenshot Vincent sent is this bug.

**Fix:** delete the breadcrumb. The H1 is the page title; a second copy of it in
the chrome is dead weight. Where there is real hierarchy — replay belongs to a
run — the page already renders a `.back` link, which is the correct affordance
and is the one we keep.

### 1.2 Deck exploration has no address

`/decks/[file]` exists and is good. Nothing links to it from the nav. The only
ways in are:

- the `Cards` pill on a tile inside `/new` (the *simulation setup* page), and
- an "Open deck →" link inside a hover popover that is `display: none` below
  980px — so on any phone or tablet the popover path does not exist.

Browsing your decks is a first-class job. It is currently a side-effect of
configuring a gauntlet.

### 1.3 The goldfish sandbox has no address

Same story: `/playtest/[deck]` is reachable only from a deck page's button or
from that same hover-only popover. It is a whole mode of the product with no
front door.

### 1.4 Filenames, ports and job ids are on screen as if they were content

Observed, verbatim, in the running app:

| Where | What the user sees | Source |
|---|---|---|
| Run report sub-line | `· sim_20260801_193328.json ·` | `app/results/[file]/page.tsx:236` |
| Run report footer | `sim_20260801_193328.json` | `:567` |
| Deck page sub-line + footer | `atraxa_counters.dck` | `app/decks/[file]/page.tsx:161,278` |
| Playtest sub-line + footer | `atraxa_counters.dck` | `app/playtest/[deck]/page.tsx:308,427` |
| Rules footer | `rules_qa` | `app/rules/page.tsx:310` |
| Import footer | `parser: convert_decklist.py` | `app/import/page.tsx:550` |
| Run status footer | `job 4f2c…` | `app/runs/[id]/page.tsx:522` |
| Replay footer | `sim_…json · game 1 of 6` | `app/results/[file]/replay/[game]/page.tsx:503` |
| `/new` section header | `Engine: 127.0.0.1:8484 · change · 3,152 rules loaded` | `app/new/page.tsx:376–394` |

**Rule to adopt:** *a filename, port, job id or script name is an address, not
content.* It never appears in a heading, a sub-line, or the footer. The footer
carries the two legal lines and nothing else. Addresses go in exactly one place
per page — a `Run details` / `Deck details` disclosure at the foot of the page,
closed by default — for the person who needs to find the file on disk.

The engine base URL is a real setting, not debug output, but it does not belong
in a section header repeated on two pages. It moves to one place: the nav
overflow ("Engine" item), which opens the same inline control.

## 2. Proposed navigation

Five destinations, all nouns, all places:

```
Decks      /decks        gallery of every deck. Import is the primary here.
Simulate   /new          pick 2–4, set games, run. (route kept; label changes)
Playtest   /playtest     deck chooser → /playtest/[deck] sandbox
Results    /results      run history → report → replay / telemetry / coaching
Rules      /rules
```

Changes from today:

- **New run → Simulate.** Today's "New run" is a verb in a list of nouns, and
  the page it points at does two jobs (browse decks, configure a run). Browsing
  moves to `/decks`; `/new` keeps only the picker it needs.
- **Import stops being a peer.** It is one action on decks, not a destination
  alongside Results and Rules. `/import` keeps working (deep links, the
  `?deck=` handoff to `/new`) but is reached from `/decks` as its primary
  action. It leaves the top-level nav.
- **Decks and Playtest are added.** Net top-level count goes 4 → 5.

On the home hub, "Explore decklists" currently points at `/new` — the same
destination as "Run new simulation". Two of four buttons going to one place is
the clearest symptom of 1.2. It repoints at `/decks`, and a fifth affordance is
not added: the hub stays four.

### Mobile nav

At ≤ 720px the nav links collapse into a disclosure button in the top bar that
opens a full-width sheet directly beneath it — same `--bar-instrument` surface,
same `.navlink` rows at `--control-h` (44px). No bottom tab bar: this is a
tool used in sessions on a desk more often than a thumb-driven feed, and a
bottom bar is the single loudest "app template" tell in `design_principles.md`
Part 1.

The wordmark stays. Today at 390px the wordmark is dropped and only the mascot
survives, which is backwards — the brand is the one thing that should never be
the first casualty.

## 3. Mobile failures, in severity order

Measured at 375–533px.

1. **Data tables hide their payload.** `/results` renders a 5-column table
   inside `.tblwrap { overflow-x: auto }`. At 375px only the *Run* column is
   visible. Winner, games, when and Watch are all off-screen behind a scroll
   nobody discovers. Nine consecutive rows read `Kilo vs Atraxa vs Ur-Dragon vs
   Meren` with nothing to tell them apart. Same failure on the run report's
   Games table (6 cols) and the Win conditions table (6 cols).

   **Fix:** at ≤ 720px the same `<table>` markup renders as stacked rows — each
   row becomes a block with the run title on line 1 and winner · games · when on
   line 2, the whole row a link. Pure CSS on the existing markup; no page
   changes. Column headers hide; each cell carries its label via
   `td::before { content: attr(data-label) }` where the label isn't obvious.
   Wide analytic tables that genuinely need a grid (Win conditions) keep the
   scroll but gain a visible "scroll for more →" cue and a sticky first column.

2. **`.figs` renders a broken grid at 2 columns.** `.fig + .fig` puts a
   left border on every cell after the first; at `grid-template-columns: 1fr 1fr`
   that lands a border on cell 3, which is the start of row 2. Visible
   misalignment on every run report on mobile.
   **Fix:** border via `:nth-child` per row, or `gap` + a wrapper border.

3. **The run button is below 29 deck tiles.** On `/new` the right rail (games
   select + primary) is a second grid column that stacks *after* the gallery at
   ≤ 980px. On mobile you scroll past every deck to reach the action.
   **Fix:** once ≥ 1 deck is seated, the action collapses into a sticky bar at
   the bottom of the viewport — seat count, games select, primary. Same
   components, `position: sticky; bottom: 0` on the existing `.ctarow`.

4. **The replay is unusable.** `.tbl.p4` stays 2-col at all widths, so seat
   plates overlap ("40 life · 0 on board" written over the next seat's text).
   The transport bar's tick labels collide with the clock. The lede says "Use
   space to play; arrows step events" on a device with no keyboard.
   **Fix:** `.tbl` → 1 column at ≤ 720px; transport wraps to two rows with the
   scrubber full-width; keyboard hint hidden behind
   `@media (hover: hover) and (pointer: fine)`.

5. **The splash eats a full screen before it says anything.** At 390px the
   mascot + wordmark occupy ~700px of a 844px viewport. The tally bar below it
   scroll-snaps horizontally and clips mid-word — "29 decks on this engir".
   **Fix:** mascot to `clamp()`; tally to a 2×2 grid at ≤ 720px, no scroll.

6. **Three of four hub buttons glow.** `DESIGN_SYSTEM.md`: *glow marks only the
   primary action and live activity.* `action-btn--primary`, `--violet` and
   `--blue` all carry a `box-shadow` glow, so nothing reads as primary.
   **Fix:** glow stays on `--primary` only; violet and blue keep their border
   colour and drop the shadow. Token-level change, no new colour.

7. **Touch targets under 44px.** `.dg-view` "Cards" pill is 24px, `.pt-mini`
   26px, `.vbtn` 34px, `.tab` ~40px. `--control-h: 44px` already exists as the
   token; these become 44 under `@media (pointer: coarse)`.

8. **Hover-only affordances that are dead on touch.**
   - `.pt-card .cbtns` (add/remove counter) is `display: none` until `:hover` —
     on a phone there is no way to put a counter on a permanent.
   - `.dl-pop` decklist popover is hover-triggered and `display: none` below
     980px, so its "Open deck →" and "Playtest →" links do not exist on mobile.
     Both destinations get real nav entries (§2), which is the actual fix.

9. **The deck gallery degrades to 29 grey rectangles.** `GET /decks` is
   returning `commander: null` for all 29 decks on the local engine, so every
   tile renders an empty 16:10 box with a name strip. Two separate things:
   - *Data:* `_list_decks()` calls `combos.parse_dck`, which parses these files
     correctly in isolation — so the running engine is likely stale. **Verify on
     the VM before assuming a bug.**
   - *Design:* regardless of cause, "no art" must not mean "empty box". The
     fallback plate shows the deck name, colour-identity pips and card count on
     `--surface-obsidian`. A gallery whose entire premise is art needs an
     honest state for when there is none.

## 4. Smaller things worth fixing in the same pass

- **`/results` rows are indistinguishable.** Four runs titled `Kilo vs Atraxa vs
  Ur-Dragon vs Meren`. The date is the differentiator and it's the 4th column.
  Put the date in the row's second line on every width.
- **Home's "Top decklists" rows link to `/results?q=<name>`.** The heading says
  decklists; clicking one should open the deck. Repoint at
  `/decks/<file>`; keep "see its runs" as the secondary.
- **`.deck-row__thumb`** is a hardcoded diagonal-stripe placeholder where
  commander art belongs. Same fallback plate as §3.9.
- **`/rules` wastes its right column.** "Rule text" is an empty panel with two
  paragraphs of apology until you ask something. Collapse to one column until
  there's an answer to put beside.
- **The `.sh` "right" slot is overloaded on `/new`** — engine address, rules
  count and an import link in a section header. All three leave (§1.4, §2).
- **`/new`'s lede references a `Cards` button** that the new IA turns into
  "open the deck", so the copy updates with it.

## 5. What this touches

Structural, no visual change:

- `web/components/Chrome.tsx` — drop breadcrumb, new NAV, mobile disclosure
- `web/app/decks/page.tsx` — **new**: the gallery, lifted out of `/new`
- `web/app/playtest/page.tsx` — **new**: deck chooser
- `web/app/new/page.tsx` — picker only; sticky action bar; drop the engine row
- `web/app/globals.css` — one new `@media (max-width: 720px)` block, a
  `@media (pointer: coarse)` block, the `.figs` border fix, glow removal on two
  action-btn variants. No new tokens.
- Every page's `<Footer right=…>` — removed; addresses move to a details
  disclosure.

Verification loop is unchanged: `cd web && npm run verify`, plus a real-pointer
pass at 390px and 1280px per the `ui-review` skill before the PR.
